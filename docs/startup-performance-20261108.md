# 启动优化与实测（2026-11-08）

> 本文记录前一阶段的实现和测量。当前正常启动已取消逐文件扫描，最新策略与结果见 [轻量启动与完整诊断](startup-integrity-20261108.md)。

本机 Windows x64、Debug 构建、Node 24.18.0、DSH 0.2.1-rc.2 的隔离测试中，充分预热后的启动到界面挂载中位数从 **12.75 秒降到 10.95 秒**，减少约 **1.8 秒 / 14.1%**。运行时包含 63,598 个文件。完整运行数据保存在 [JSON 报告](startup-performance-20261108.json)。

## 实现

- 受管理运行时已在选择阶段验证清单与文件，启动时直接使用清单版本，省去一次 `node bin.js --version`。全局、自定义等可变运行时仍重新探测版本。
- 用 Node `--import` 在真正的 DSH 入口执行前准备插件临时补丁，省去独立预处理进程，也复用上游模块缓存。实际入口的 `import.meta.main` 和参数不变。启动参数在导入上游模块前消费，Worker 不会重复写补丁；预处理失败会阻止后端启动。
- Node 可执行文件的哈希记录使用现有 Windows DPAPI 保护，绑定路径、文件身份、大小、修改时间和 ChangeTime。缓存命中时不再读取整个可执行文件；文件变化、记录缺失或损坏时完整计算哈希。校验后的哈希仍须匹配所选运行时清单。测量中缓存命中约 1 毫秒，首次完整计算约 1.5 秒（Debug 构建）。
- 后端默认在应用数据目录的 `node-compile-cache` 中保存 Node 模块编译缓存。后端就绪后刷盘，使宿主结束进程树时不丢失缓存。保留用户的 `NODE_COMPILE_CACHE` 与 `NODE_DISABLE_COMPILE_CACHE` 设置；旧 Node 缺少刷盘 API 时跳过这项可选操作。Node 按源文件与引擎版本使缓存失效。
- `DSH_DESKTOP_DEBUG` 日志增加进程启动、窗口创建、Node 探测、运行时解析、版本获取、子进程创建和后端就绪的时间点。

运行时文件内容和目录校验没有删减。缓存命中后，6.4 万文件的检查仍约需 5 秒，是本次 Debug 测量中最大的剩余开销。未改动窗口与后端的同步顺序。

后续的窗口与后台准备并行改动及独立测量见 [并行启动验证](startup-parallel-20261108.md)。上面的结果保留为第一轮优化记录。

## 测量方法和边界

基线来自提交 `a4bab15dcbbe4a91385403e0b8a8f42a143cfb6b`，仅增加与优化版相同的计时及隔离测试支持。两版使用同一个隔离 Profile、同一个受管理运行时、同一个 WebView2 数据目录，并分别加载对应版本的桌面插件资源。没有执行模型请求。

| 测量 | 次数 | 窗口可见中位数 | 后端就绪中位数 | 界面挂载中位数 | 文件检查中位数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 初始基线 | 5 | 0.639 秒 | 14.333 秒 | 14.647 秒 | 5.927 秒 |
| 优化版 | 5 | 0.639 秒 | 10.703 秒 | 10.952 秒 | 5.237 秒 |
| 优化版测量后复测基线 | 3 | 0.646 秒 | 12.532 秒 | 12.749 秒 | 5.135 秒 |

每轮退出整个测试应用，再启动新进程；统计前先预热。界面挂载由浏览器检查 `__DSH_UI_STATE__` 与 React 根节点内容确认，窗口和后端状态按 50 毫秒轮询，并包含少量 IPC/CDP 观察开销。这不是某一按钮完成交互的测量。

首次对比显示约 25% 差异，但再次测量旧版后确认系统预热也带来了收益，因此以 **14.1%** 作为主要结果。文件检查代码未调整，不将其计时变化归因于本次优化。这些数据不代表首次安装、系统冷启动或 Release 安装包；新缓存第一次建立时仍有完整校验和编译成本。

## 复现

`tools/startup-benchmark.mjs` 会在仓库 `src-tauri/target` 内创建隔离数据目录，首次通过生产冻结流程准备受管理运行时，之后复用它。参数为：

```text
node tools/startup-benchmark.mjs ROOT LABEL EXE [RESOURCE_PROJECT] [ROUNDS]
```

例如在构建 Debug 程序后：

```powershell
node tools/startup-benchmark.mjs src-tauri/target/perf-investigation after src-tauri/target/debug/deepseek-harness-desktop.exe . 5
```

对比前后版本时保留同一个 ROOT，分别传入对应可执行文件和资源项目根目录。默认使用 PATH 中的 Node 与用户 npm 全局安装的 DSH 作为只读运行时来源，可用 `DSH_DESKTOP_DSH_BIN` 指定其他实际安装。浏览器自动化依赖 Playwright，可通过 `PLAYWRIGHT_PATH` 指定模块路径。

Debug 验证程序按隔离目录生成独立单实例标识，并跳过系统深链注册，可与开发实例并存。本次开发程序占用了原可执行文件，因此验证副本仅改了 Cargo 包名，并共享依赖构建缓存。Release 不包含这部分测试入口。
