# 轻量启动与完整诊断（2026-11-08）

已确认可用的受管运行时，正常启动不再遍历依赖目录。相同隔离 Profile 下，本机 Debug 版五轮复测的界面挂载中位数从 **9.835 秒降至 6.385 秒**，减少 **3.450 秒 / 35.1%**。

这是在此前窗口与后台准备并行、版本复用和模块编译缓存基础上的增量收益。本文取代前两份报告中“每次启动仍检查所有文件”的当前行为说明；前两份报告保留为历史测量。

## 校验策略

| 时机 | 行为 |
| --- | --- |
| 安装、更新、尚未确认成功的首次运行 | 保留依赖冻结、完整清单和文件完整性校验；后端及界面确认成功后才提交启动选择。原有可靠文件身份缓存仍可复用。 |
| 已提交版本的正常启动 | 检查选择记录、清单版本/架构、指纹绑定、入口及其祖先路径，运行 Node 版本探测，然后实际启动后端；不读取 inventory.json、不遍历依赖、不读取校验缓存。 |
| 后端启动失败或退出 | 先显示失败状态，再在后台执行完整内容校验，结果可在故障诊断中查看。 |
| 故障诊断 → 重新检测 | 完整读取并计算文件内容哈希，检查目录布局、文件缺失/新增、清单及绑定；即使已有校验缓存也重新读取内容。 |

轻量入口选择在本次所有十轮测量中均约 1 毫秒。Node 的可执行文件哈希也不再作为正常启动门槛：允许满足最低版本要求的 Node 更新，由实际后台运行检验兼容性；完整诊断会单独提示 Node 与安装时不同，不把这种变化误报为依赖文件损坏。

无效的选择记录或缺失入口会明确报错并保留原选择，避免静默切换到全局安装。有效的显式入口配置仍保持优先；没有受管选择记录时仍使用原有发现及安装流程。

失败诊断不持有维护锁，允许用户重试。诊断工作串行化，启动/重试使先前诊断失效，即使尚未分配新的后台实例，迟到的检查结果也不能覆盖当前状态。该扫描可能继续完成读取，但其结果会被丢弃。正常成功启动不会另外安排后台全量扫描。

这项优化有意不在正常启动前发现未被加载的依赖损坏；这类问题由后续实际使用或手动完整诊断发现。全局/自定义安装没有受管清单，诊断会显示无法验证完整性，不声称文件已验证。清单版本用于受管版本展示，不额外执行一遍 dsh CLI。

## 实测

Windows x64、Node 24.18.0、DSH 0.2.1-rc.2、Debug 构建，包含 63,598 个文件的同一受管运行时。同一隔离 Profile、模块编译缓存和 WebView2 数据目录，每轮退出并创建新进程，每组测量前预热。执行顺序为轻量版、原版、轻量版复测；测量时没有并行运行本次的构建或测试。

| 版本 | 轮数 | 窗口可见中位数 | 后端就绪中位数 | 界面挂载中位数 | 全目录检查中位数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原版：每次检查所有文件 | 5 | 0.640 秒 | 9.540 秒 | 9.835 秒 | 3.838 秒 |
| 轻量版，首次测量 | 5 | 0.639 秒 | 6.092 秒 | 6.366 秒 | 未执行 |
| 轻量版，反向复测 | 5 | 0.639 秒 | 6.082 秒 | 6.385 秒 | 未执行 |

界面挂载以 UI bridge 存在且 React 根节点有内容为观测条件，计时包含进程创建、状态轮询及 CDP 连接开销。这是本机预热后的 Debug 测量，不代表 Release、首次安装或系统冷启动耗时。与历史报告不同批次的绝对数字不能直接相减；本轮使用保存的上一版程序重新建立基线。

逐轮数据及原生场景结果见 [JSON 报告](startup-integrity-20261108.json)。

## 验证与复现

- Rust：265 项通过，5 项按原配置忽略；随后补充运行 Node 校验缓存回归测试，1 项通过。
- 诊断、国际化、预加载和启动页面相关 JavaScript 测试：18 项通过。
- 使用真实受管运行时和 Tauri IPC 验证七项行为：缓存缺失、缓存损坏、手动重算全部文件哈希、发现额外文件、入口代码损坏后自动诊断、修复重试及旧结果失效、入口缺失时拒绝静默切换。测试结束后恢复隔离运行时的入口与原校验缓存，启动选择始终不变。
- 为避免覆盖运行中的开发程序，使用只更改 Cargo 包名的源码副本构建验证程序，共享依赖编译缓存。

```powershell
# 自动准备隔离的真实运行时并测量五轮，ROOT 必须位于 src-tauri/target 内。
node tools/startup-benchmark.mjs src-tauri/target/perf-investigation lightweight src-tauri/target/debug/deepseek-harness-desktop.exe . 5
# 使用上述已提交的隔离运行时测试损坏、诊断和重试。
npm run test:startup-integrity -- src-tauri/target/perf-investigation src-tauri/target/debug/deepseek-harness-desktop.exe
```

测试仅修改指定 target 内的隔离运行时，不修改用户正在使用的 Profile，不发送模型请求。

验证结束后已两次执行 `npm run clean:target`，清理脚本因现有 `tauri dev`、`cargo run` 和桌面进程仍在运行而拒绝删除。本次测试进程均已退出；`src-tauri/target/perf-investigation`、`src-tauri/target/perf-baseline` 等临时材料暂保留，未终止用户开发进程，未删除开发/打包缓存。正式报告和复现工具已保存于 docs/ 与 tools/。
