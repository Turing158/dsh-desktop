## 这是什么？

**这是我为日常自用构建的 dsh 桌面端，主要围绕自己的使用习惯和实际需求持续完善。** 项目通过 **DeepSeek 4.1 Flash** 和 **GPT-6-astra** 辅助开发与构建。

如果你在用 **DeepSeek Harness（dsh）** 写代码，可能希望它用起来更像一个完整的桌面工作台：任务完成时主动提醒你，改完代码后直接看差异，需要运行命令时展开终端，发现一处小问题就顺手编辑文件。

DeepseekHarness Desktop 就是围绕这些日常操作做的增强。它启动 dsh 的 Web 服务，通过独立桌面窗口呈现原有界面，再加载本项目的桌面插件，补充通知、终端停靠、更改面板、文本编辑、插件开关和手机访问等能力。

**AI 对话、模型调用、工具执行和会话管理仍由 dsh 提供；本项目主要完善桌面操作体验，并为缺少相关功能的旧版补充入口与实现。** 模型、API 和权限策略继续通过 dsh 配置。

> 下文的“原版 dsh”指**未加载本项目增强插件的 `dsh web`**。上游也有其他发行形式，功能会随版本变化；这里对比的是本项目实际增加的能力，不把 dsh 已有的对话、文件预览、主题、插件系统或新版终端算作本项目原创功能。

## 相比原版，增加了什么？

| 能力 | 原版基础 / 使用场景 | 本项目增加的内容 |
| --- | --- | --- |
| 🪟 **桌面窗口与托盘** | `dsh web` 通过浏览器访问 | 独立 Windows 窗口、自定义标题栏、窗口控制、系统托盘与单实例处理；关闭窗口后可留在后台继续工作。 |
| 🔔 **系统通知** | 需要关注会话中的任务与提问状态 | 将任务完成、运行错误、待回答问题和计划待确认转成 Windows 通知，离开主界面也能收到提醒。 |
| 💻 **终端与底部面板** | 较早版本没有原生终端；新版已提供终端 | 缺少原生终端时提供本项目的交互式终端；已有原生终端时复用它，并增加底部停靠、多标签、默认 Shell 与打开位置设置。 |
| 📝 **更改审阅** | 需要知道“这次会话究竟改了哪些文件” | 增加“当前会话 / 未提交 / 暂存区 / 提交记录”四种视图，查看累计差异、增删行数、操作历史和 Git 提交图。 |
| ✏️ **直接编辑文件** | 在右侧栏查看文本或代码后，还想顺手修改 | 在原有文本、代码预览位置接入编辑器，支持语法高亮、查找替换、撤销重做和 `Ctrl+S` 保存。 |
| 📱 **局域网访问入口** | Web 服务需要配置地址与连接方式 | 在桌面设置中选择网卡、端口和可信 Host，生成登录链接与二维码，并为手机补充布局、菜单和输入适配。 |
| 🧩 **可视化插件开关** | dsh 已有插件系统和插件清单 | 增加内置增强开关、可管理插件的持久化启停、运行状态与重启提示；宿主支持安装服务时提供 `dshmarket` 安装入口。 |
| 🎨 **外观定制** | dsh 已有主题与基础外观设置 | 扩展字号范围，增加背景图片、输入框材质与透明度、动画偏好，以及完整 / 简洁标题栏。 |
| 🔗 **桌面快捷操作** | 会话与项目已在 dsh 中管理 | 增加本机会话深链接、项目打开方式，并为支持会话导出的 dsh 接入原生保存文件夹选择与下载完成反馈。 |
| 📦 **分发与启动** | 运行 dsh 需要准备环境并启动服务 | 提供安装包、离线便携包和单文件版；启动时检测运行环境、显示启动或安装进度，缺少 dsh 时可自动安装。 |

## 对低版本 dsh，补齐了哪些能力？

**旧版缺少功能时提供补充，新版已有能力时尽量复用。** 最典型的是终端：本项目根据实际注册的终端能力选择实现，不只看版本号。

| 旧版或当前运行环境缺少什么 | 本项目如何补充 | 升级后的处理 / 适用条件 |
| --- | --- | --- |
| **没有原生交互式终端** | 提供基于 Windows ConPTY 与 xterm.js 的终端，可在右侧栏或底部执行命令。 | 检测到 dsh 原生终端后，底部面板改用原生组件与服务，避免出现两套重复终端入口。 |
| **没有按会话累计的更改面板** | 通过独立插件记录支持的文件工具修改，按文件汇总跨轮变化，保留差异和操作历史。 | 需要宿主的工具、会话和通信接口；记录从插件接入后开始，不凭当前文件反推接入前的修改。 |
| **文本预览只能看、不能改** | 在兼容的文本 / 代码预览插槽中加入编辑、搜索与保存。 | 需要对应预览插槽和文件服务；保留原有预览类型，文本编辑有文件大小与编码限制。 |
| **插件清单缺少持久化开关** | 增加可管理条目的启停状态保存，以及“已应用 / 需要重启 / 失败”等反馈。 | 按宿主能力处理热切换；缺少安装服务时会提示，不承诺所有旧版都能安装插件市场。 |
| **缺少桌面提醒、托盘和本机会话链接** | 由桌面宿主与插件补充，无需旧版先实现这些桌面功能。 | 仍依赖可用的 dsh 事件与会话接口，具体行为以运行时能力为准。 |
| **新旧设置、导航接口不一致** | 适配旧版设置注册方式与新版配置方式，兼容两代会话导航接口，保存桌面外观及终端偏好。 | 恢复草稿、附件和布局前检查所需接口；缺少必要能力时提示原因并取消操作。 |

版本需要分开看：**`0.1.1` 是本项目的桌面版本，不是 dsh 版本。** 历史适配记录包含 dsh `0.1.5-rc.2`；当前代码核对与近期集成记录主要基于 `0.2.0-rc.2`，离线运行时清单也固定为该版本。部分旧接口回退通过行为测试覆盖，不代表所有旧版本和所有功能组合都已逐一实机验证。

## 日常使用体验优化了什么？

### 终端可以一直放在手边

在会话顶部打开底部终端，或通过右侧栏进入终端；默认位置可在设置中选择。支持多标签、调整底部高度，以及选择可用的 PowerShell、PowerShell 7、CMD 等 Shell。

- **按项目保留终端**：切换项目、收起面板后，再展开可继续使用对应终端。
- **复制与中断分清楚**：`Ctrl+C` 有选区时复制，无选区时交给终端中断命令；支持右键复制 / 粘贴与键盘菜单。
- **新旧终端保持一致的入口**：新版复用 dsh 原生终端，旧版使用本项目终端，并提供默认 Shell 和打开位置偏好。
- **手机输入适配**：补充移动端终端输入与软键盘处理；实际可用操作仍取决于所用终端实现。

### 看清一次会话留下了什么改动

右侧栏的 **更改** 面板把几种不同的问题分开呈现：

| 视图 | 适合回答的问题 |
| --- | --- |
| **当前会话** | 这个会话从开始记录到现在，累计改了哪些文件？同一文件跨轮合并展示，并可展开操作历史。 |
| **未提交** | 当前工作区相对 Git `HEAD` 有哪些差异？这里包含已暂存与未暂存共同形成的工作区最终状态。 |
| **暂存区** | 相对 `HEAD`，哪些内容已经进入 Git 暂存区？ |
| **提交记录** | 仓库有哪些提交、分支与标签？某次提交具体改了什么？ |

没有 Git 仓库时，仍可查看已经采集的会话更改；Git 相关视图会说明不可用原因。会话累计行数按前后内容重新比较，不简单叠加每次操作的增删行数。

右键更改列表中的文件，可打开文件、在独立标签页查看更改，或展开 / 收起行内差异；也可通过 **打开** 子菜单选择本机应用，或在资源管理器中定位文件。独立更改标签页保留打开时的范围（当前会话、未提交或暂存区）。

对于 Shell 和其他扫描得到的变化，界面会区分“已确认”与“执行期间观察到的变化”。交错修改、缺少基准或超出采集预算时保留说明，不把不完整记录当作完整结果。

### 在预览文件的地方直接修改

打开工作目录中的文本文件后，可在代码或纯文本视图中直接编辑。代码模式支持 JavaScript / TypeScript、Rust、Python、C / C++、Java、Go、JSON、YAML、Markdown 等常见格式。

编辑器会标记未保存内容，关闭标签或重新读取前询问如何处理。保存时检查磁盘版本；如果文件已被其他程序修改，会保留当前编辑并提示冲突。支持保留 UTF-8 BOM 与原有换行格式。

当前可编辑范围为**所属会话工作目录内、不超过 2 MiB 的 UTF-8 普通文本文件**。

HTML / HTM 文件支持在右侧栏切换编辑与预览：编辑时点击 **预览 HTML**，或在查看器菜单中选择 **HTML**；选择 **代码** 或 **纯文本** 返回编辑，并可用 `Ctrl+S` 保存。未保存的修改也会直接显示在预览中。渲染沿用 dsh 的 HTML 预览能力与代码工作工具设置。

### 手机打开后，也能正常使用

手机端使用同一套 dsh Web 界面，并增加窄屏侧栏、触控菜单、主题快捷切换、软键盘视口和按钮布局适配。针对部分浏览器缺少的新 API 提供兼容补充，改善插件加载失败、项目或会话列表一直等待的问题。

文件预览与侧栏动画也减少了不必要的全页面扫描，降低大段代码预览时的额外界面开销。这些优化针对已发现的兼容问题，不表示支持任意老旧浏览器。

### 外观与桌面操作更顺手

- **个性化外观**：主题跟随系统或手动切换，内容字号可选 10–18 px；支持背景图片、玻璃 / 磨砂 / 透明 / 不透明输入框材质及相关调节。
- **动画可控**：可跟随系统，也可手动开启或关闭，菜单和侧栏提供相应的过渡处理。
- **中文 / English**：桌面新增界面、启动页、通知和托盘文案跟随 dsh 的语言偏好。
- **项目打开方式**：可在资源管理器或已检测到的编辑器中打开项目，如 VS Code、Cursor 等。
- **会话深链接**：复制 `deepseekharness://session/<id>`（省略会话 ID 的 `session-` 前缀），在本机直接回到对应会话；旧格式链接仍可打开。它不是分享会话内容的网页链接。
- **后台继续运行**：关闭主窗口后留在托盘，需要完全结束程序时使用托盘菜单中的“退出”。

设置中的 **“切换成原版”** 用于切换外观，不是回退 dsh 版本，也不是卸载全部桌面插件。需要关闭某项可选增强时，在插件设置中操作。

## 快速上手

### 1. 选择适合的版本

| 分发形式 | 适合谁 | 运行环境 |
| --- | --- | --- |
| **离线便携包** `DeepseekHarness-portable-win-x64.zip` | 希望解压后直接启动，不单独准备 Node.js / WebView2 的用户 | 自带 Node.js、npm、dsh 及其依赖、固定版 WebView2。必须完整保留解压目录中的 `runtime` 和 `dsh-plugin`。 |
| **Windows 安装包** `DeepseekHarness_*-setup.exe` | 希望通过安装程序使用的用户 | 使用系统运行环境；需要 Node.js 22+ / npm 和 WebView2，缺少 dsh 时进入自动安装流程。 |
| **单文件版** `deepseek-harness-desktop.exe` | 已有运行环境，希望只携带一个 EXE 的用户 | 桌面插件内嵌，启动时释放到应用缓存；仍需要系统 Node.js 22+ / npm 和 WebView2。 |

当前目标平台是 **Windows 10 / 11 x64**，终端需要系统支持 ConPTY。Git 和 PowerShell 7 不随包提供；使用对应能力时请自行安装。

**“离线便携”指启动所需运行环境随包提供，不包含 AI 模型。** 调用在线模型、安装社区插件等操作仍可能需要网络和对应配置。

### 2. 启动并配置 dsh

解压便携包后运行其中的 EXE，或安装后启动应用。启动页会显示环境检测与服务启动状态；使用系统运行环境的版本若未找到 dsh，会显示自动安装进度。

进入界面后，按 dsh 的正常流程配置模型服务、API 信息和工作目录，创建或打开会话即可使用。桌面增强会随本应用加载，无需另外安装通知 Hook。

自定义供应商的模型也可在输入框原有的模型菜单中选择 **推理等级**：`Off / Low / Medium / High / Xhigh / Max`，默认选中 `High`（已配置为这六档之一的默认值仍沿用）。这些档位固定提供，不预先检测模型能力；选择后按配置的 API 协议发送，接口拒绝会显示原有错误，接口忽略参数时则可能不生效。选择按会话保存，内置供应商仍使用原有的模型能力目录。

系统通知会在首次启动时自动创建当前用户的 `DeepseekHarness Desktop` 开始菜单快捷方式，单文件版也无需先安装。后续启动只检查通知身份、EXE 路径和图标；快捷方式正确时不会重写，缺失、损坏或 EXE 移动后才修复。通知仍遵循 Windows 的通知开关和勿扰设置。

### 3. 使用常用增强

- 在 **设置 → 外观** 调整主题、字号、背景、材质和标题栏。
- 在 **设置 → 插件** 管理内置增强与可管理的 dsh 插件；需要重启的变更会明确提示。
- 在会话顶部打开 **底部终端**，或从右侧栏进入 **终端 / 更改 / 文件**。
- 需要在后台运行时关闭窗口；通过系统托盘重新显示主界面或退出应用。

使用系统 dsh 的版本还提供 `latest` / `next` 通道检查与安装入口。该更新操作通过 npm 更新全局 dsh，完成后需退出并重新启动；如果应用使用单独指定或私有安装的 dsh，应核对实际运行路径。离线便携版使用随包 dsh，更新时替换完整便携包。

## 用手机或平板连接

1. 在电脑端打开 **设置 → 远程控制**，开启局域网访问。
2. 选择电脑当前使用的局域网 IPv4 和端口，点击 **应用并重启 DSH**，首次启用时确认。
3. 手机与电脑连接同一局域网，扫描二维码或打开完整登录链接。

网页中的“选择工作区目录”提供 **后退、前进、上一级、刷新** 按钮；点击 **此电脑** 可返回电脑端的盘符列表，从盘符根目录点击“上一级”也会回到该列表。支持直接输入完整路径、返回主目录、新建文件夹和显示隐藏文件。

应用远程配置会重启 dsh，**中断正在运行的 AI 任务与连接**。应用会先尝试保存支持的草稿、附件和界面状态，保存失败时取消操作；终端的保留与恢复取决于所用实现及其生命周期。

局域网功能默认关闭，当前使用 HTTP。**持有登录链接或二维码的设备可以访问会话并在这台电脑上执行任务**，请仅在可信局域网启用并妥善保管链接。当前不提供外网直连；重启也不等于撤销设备已有登录状态。

## 数据与当前边界

- **会话与配置**：沿用 dsh 的数据目录和 profile；桌面外观、终端偏好、插件开关、远程配置及更改快照分别由相应组件保存。便携分发不表示所有用户数据都会写在 EXE 旁边。
- **更改采集**：支持结构化文件工具、部分工具执行期间的本地扫描及可识别的后台任务。交互终端、外部编辑器、脱离受管任务的进程和远程文件系统不保证完整采集或精确归属；不会补录插件接入前的历史。
- **Git 面板**：当前用于浏览差异与提交记录，不提供完整的暂存、提交、合并和推送工作流。
- **极简模式**：默认隐藏窗口并保留后台。另有默认关闭的实验性 WebView 销毁 / 恢复路径，受草稿、面板和活动终端等状态限制，不能将默认模式理解为完全释放 WebView 内存。
- **兼容范围**：功能取决于 dsh 的实际扩展接口。旧版补齐不等于绕过所有版本差异；第三方插件的表单、面板和状态恢复也可能需要单独适配。

## 给开发者

桌面宿主使用 **Rust + Tauri 2**，通过系统或随包的 **WebView2** 显示 dsh Web 界面。增强逻辑位于 `dsh-plugin/`，以启动覆盖层和插件形式接入。

| 目录 / 文件 | 用途 |
| --- | --- |
| [`src-tauri/src/`](src-tauri/src/) | dsh 启动、原生窗口、托盘、通知、终端、远程配置和状态恢复。 |
| [`src-tauri/ui/`](src-tauri/ui/) | 环境检测、安装进度与启动页面。 |
| [`dsh-plugin/`](dsh-plugin/) | 外观、标题栏、终端、更改面板、文件编辑、插件管理与语言适配。 |
| [`dsh-plugin/desktop-notify.patch.yml`](dsh-plugin/desktop-notify.patch.yml) | 桌面应用加载的 dsh 覆盖层。 |

### 本地开发

准备 Node.js 22+ / npm、Rust stable（Windows MSVC 工具链）、Visual Studio C++ 生成工具、Windows SDK 和 WebView2。

在仓库根目录执行：

```powershell
npm install
npm run dev          # 限制编译并发与优先级，减少开发时的资源占用
npm run dev:fast     # 直接运行 tauri dev
```

启动时自动查找可用的 dsh；非标准安装位置可使用 `DSH_DESKTOP_NODE` 指定 Node 可执行文件，使用 `DSH_DESKTOP_DSH` 指定 dsh 入口脚本。数据根遵循 dsh 的 `DSH_HOME` 设置。

### 检查与构建

```powershell
npm run test:plugin     # Node 插件与行为测试
npm run test:rust       # Rust 测试
npm run check:menus     # 菜单检查
npm run build:terminal # 构建终端、文件编辑等前端资源
npm run build          # 构建桌面程序与 NSIS 安装包
```

开发和正式构建已通过 Tauri 钩子自动执行前端资源构建。`tools/` 中另有真实 dsh、终端、远程访问和页面恢复等集成检查脚本，应按变更范围选用；普通单元测试通过不等于所有版本的实机兼容性都已验证。

Windows 原生通知可单独验证（会发送一条测试通知，临时开始菜单快捷方式与测试通知会自动清理）：

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --features single live_windows_notification -- --ignored --nocapture --test-threads=1
```

关闭桌面实例后，可运行 `node tools/notification-package-smoke.mjs pack/single/deepseek-harness-desktop.exe` 验证单文件成品。检查会连续启动两次，确认通知进入系统通知中心且快捷方式未被重复写入；使用隔离的 DSH 目录，不启动模型任务或 LAN 服务。正常通知注册会保留指向被测试 EXE。

设置环境变量 `DSH_DESKTOP_DEBUG` 为日志文件路径后启动 EXE，可查看通知注册、提交与失败记录。`[notify/registration] unchanged` 表示复用了已有注册，`[notify/submitted]` 表示系统接受了提交；是否显示横幅仍由 Windows 决定。

### 生成分发包

```powershell
.\pack.ps1                         # 离线便携包 + 单文件版 + NSIS 安装包
.\pack.ps1 -Target Single          # 只构建单文件版
.\pack.ps1 -Target Portable        # 构建便携包与安装包，不构建单文件版
.\pack.ps1 -SkipBundle             # 跳过 NSIS 安装包
.\pack.ps1 -PortableMode Thin      # 便携目录使用系统运行环境
```

产物默认收集到 `pack/portable/`、`pack/single/` 和 `pack/installer/`；完整离线 ZIP 位于 `pack/DeepseekHarness-portable-win-x64.zip`。离线运行时首次准备需要联网，后续构建会校验并复用缓存。

## 上游项目

本项目基于 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的运行时、Web 界面与插件机制构建。模型能力与核心 Agent 工作流由上游提供，本仓库聚焦 Windows 桌面集成、功能补充与使用体验优化。
