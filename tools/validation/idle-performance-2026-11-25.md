# 空闲占用优化与验证（2026-11-25）

## 实现范围

- 更新退出控制由每 100 ms 读取一次文件改为目录事件驱动，保留 2 秒兜底检查。支持原子替换、取消请求、失败确认，空闲或任务状态不明确时不会直接退出。
- 插件管理状态只在视图挂载且页面可见时每 2 秒刷新。关闭视图后停止计时器，60 秒后释放状态缓存；显示页面时重新刷新。同时适配旧设置页和 0.2.3 的独立插件页。
- 客户端热更新只观察可修改的 bundle；同一目录共用非递归观察器，保留 30 秒兜底。经过原生托管运行时选择验证的不可变 `tree` 不再重复观察和 stat。保留上游图、权限及 Remote 事件传输。
- MCP 在第一次模型步骤捕获工具列表之前启动，支持直接配置和管理器配置。并发步骤共享启动，已经取消的任务不会启动服务器；管理页手动重启立即连接。首次任务承担服务器连接时间，后续复用连接。显式 `failOnStartupError` 保持原有启动行为，旧运行时/不支持同步加载钩子的 Node 保持上游行为。已经使用的外部 MCP 不自动终止，避免中断其后台工作。
- 编辑器引擎改为首次打开文件时加载。启动客户端从 1,643,332 字节降至 39,188 字节；延迟加载引擎为 953,965 字节。引擎资产检查版本并沿用宿主认证，加载失败可重试。
- 编辑器限制未使用的干净缓冲区为 16 个、8 MiB。已订阅、有草稿、正在读取或保存的文档保留。
- 原生启动插件覆盖文件放进独立更新控制目录，避免 Windows 共享 Temp 中其他程序的写入触发额外扫描。

优化在桌面源码中默认启用；使用更新后的客户端资源和原生程序启动后生效。后端适配器覆盖测试所用的 DSH 0.2.3-alpha.2；0.2.1-rc.2 等旧版本保留原实现。`DSH_DESKTOP_IDLE_OPTIMIZATIONS=0` 可以在启动前禁用后端加载适配器，前端按需刷新和编辑器加载仍然有效。加载钩子保持 `require.resolve()` 和 `import.meta.resolve()` 指向原包，以保留浏览器插件和协议元数据发现。

没有新增生产环境的持续性能采样器。以下测量仅由独立测试脚本执行，不向用户正在运行的 Node 后端注入调试代码。

## 测量方法与解释

### 本次长测结果

DSH 0.2.3-alpha.2，托管不可变目录排除已启用。前台测量 30 秒，后台隐藏页面测量 600 秒；全部 11 组集成检查通过。原始指标摘要保存在同目录的 `idle-performance-2026-11-25.json`。

| 场景 | 后端平均 CPU | Edge 平均 CPU | 合计 | 后端工作集 | Edge 工作集合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 前台空闲 30 秒 | 0%（计时分辨率内） | 0%（有 2 个退休子进程，属下界） | 0%（下界） | 445.84 MiB | 762.43 MiB |
| 后台空闲 10 分钟 | 0.1167% | 0.0083% | 0.1250% | 437.32 MiB | 783.72 MiB |

后台时段统计的进程没有退出。后端工作集比前台样本低约 8.52 MiB，未出现持续增长；后台恢复后会话列表、HTTP 和 WebSocket 均可用。首次模型步骤包含并成功调用直接及管理器 MCP 工具，手动重启和浏览器热更新也通过。

独立用户目录、完整桌面插件覆盖、离线模型和 stdio MCP 测试服务器。使用 Windows 进程 CPU 时间差除以墙钟时间及逻辑处理器数量，口径接近任务管理器的整机 CPU 百分比。浏览器只统计本测试启动的 Edge 进程树；退休的浏览器子进程数量单独记录，若存在，其终止前 CPU 不计入这一差值，因此浏览器值是下界。工作集相加会包含共享页面，不等于独占内存。

浏览器通过独立进程及 `connectOverCDP(..., { noDefaults: true })` 启动，后台测量前确认真实 `document.hidden === true`。没有改写可见性属性或合成可见性事件。恢复后验证会话列表可用、HTTP 接口可用及活跃 WebSocket。

测量的是独立后端和 Edge 页面，不是用户整个原生桌面进程组的改动前后对照。无法据此承诺每台机器的整机占用降到某个固定值。极简模式销毁和重建界面的既有流程未改变；此测试验证隐藏页面恢复，不把它当作极简重建测试。

## 复现

在 PowerShell 中指定当前托管版本的入口，运行 `npm run test:idle-performance`。默认前台 30 秒、后台 600 秒。可以通过 `DSH_IDLE_SMOKE_VISIBLE_MS` 和 `DSH_IDLE_SMOKE_BACKGROUND_MS` 缩短功能检查，但短测不作为稳定占用结论。

设置 `DSH_DESKTOP_DSH_BIN` 为实际 `tree/node_modules/@deepseek-ai/dsh/lib/bin.js`，设置 `DSH_DESKTOP_IMMUTABLE_RUNTIME_ROOT` 为该托管版本的 `tree`。脚本在仓库 `src-tauri/target/diagnostics-*` 下保存临时结果。普通环境可以指定 `PLAYWRIGHT_PATH` 和 `DSH_IDLE_SMOKE_EDGE`。

完整回归使用仓库 `target` 下的临时目录，并设置 `GIT_CEILING_DIRECTORIES` 为该目录，避免无 Git 的测试夹具发现外层仓库。验证完成后运行 `npm run clean:target`；正在运行的用户开发程序不因清理被停止。

## 清理结果

验证任务和独立测试进程已结束，并已执行 `npm run clean:target`。脚本因两个持续运行的用户 `cargo run` 开发进程（PID 29972、31664）拒绝清理。保留 `src-tauri/target` 内本次 `diagnostics-*`、`file-editor-smoke-*`、`perf-investigation` 等临时目录；开发进程正常结束后可以重跑清理命令。没有停止用户进程，没有删除 debug/release、交叉编译和打包资源。

仓库忽略 `docs/`，因此此记录和 JSON 摘要另存到可提交的 `tools/validation/`，不依赖临时测试目录保存证据。
